# Draft: `cantos.identity.native-session-admission` (#334/#335, v1 sessions)

Module-owned inventory of [`cantos.identity.native-session-admission`](../../../../specs/behavior/catalog.json). The [root inventory](../../../../specs/behavior/inventory.md) keeps the shared authority framing; the registry owns the stable ID and lifecycle.

Turning a native Identity `AuthenticationFact` into one Server session and re-admitting that
session against a fresh `GetSecurityState`. Archived `identity_password*_postgres`
names below identify historical HTTP/fact oracles, never native acceptance. Current pure decisions
and the Turso adapter retain their separate named evidence. Model: [native_session_admission.qnt](native_session_admission.qnt).

| Classification | Authority / fact | Model consequence |
| --- | --- | --- |
| Approved requirement | [Identity auth v1](../../contracts/auth/identity-auth/v1/README.md#freshness-and-revocation-quantified): a fact is used only if `0 ≤ now − authenticated_at ≤ 30 s` (5 s ahead tolerated), else `503`; a fresh read at every login, renewal and protected admission; admit only Active with equal `instance_epoch` and `security_version`; any difference (disabled, advanced, **lower**, other epoch, unknown subject) revokes; once that write commits it is never resurrected; an outage fails closed **without** revoking; logout stays local. [Identity RPC](../../../cantos-identity/contracts/identity/v1/README.md#authentication-fact): a fact is not a session; operation/purpose binding is validated first. [ADR 0045](../../../../docs/decisions/0045-v1-email-password-sign-in.md#decision): the Studio roster is checked at login and every admission and grants nothing else. | Properties `issue-needs-fresh-bound-fact`, `admit-only-exact-active`, `mismatch-requests-revoke`, `revocation-sticky`, `outage-never-revokes`. Lifecycle stays `draft`. |
| Implemented independently of this model | Pure [`decide_issue`/`decide_admission`](../../src/platform/identity_auth/decision.rs) (precedence: subject, age, active, epoch, version; versions compare both ways); the [shell](../../src/platform/identity_auth/mod.rs) `login` (fact validation, roster, read, issue) and `confirm` (roster, read, `NOT_FOUND` → `subject-missing`, decision, then a best-effort [`revoke`](../../src/platform/identity_auth/turso.rs) `UPDATE … AND NOT revoked` whose failure is ignored); `access` refuses a revoked family before Identity is asked. | `admit` stands for `confirm`, which protected admission, Web renewal and native refresh all call. `request` (decision) and `commitRevoke` (durable write) are separate steps: properties `request-is-not-commit` and `session-changes-only-by-transition`; a revoke write for an already-ended session is a no-op, like the conditional `UPDATE`. A new login drops a request for the previous session. A test-only [pure-core observer](../../src/platform/identity_auth/decision/quint_conformance_tests.rs) is registered (#106): `--conformance` calls the real `validate_fact`, `SecurityState::from_response`, `decide_issue` and `decide_admission`, while the Studio roster, session slot, absent/unreachable Identity read, requested-versus-committed revocation and logout are a **disclosed synthetic shell**, labelled per checkpoint. It is not HTTP, cookie, SQL, RPC or E2E acceptance ([protocol](../../../../specs/behavior/observation-protocol.md#native-identity-auth-observation-protocol-v1)). |
| Finite assumption | One registered subject (1; subject 2 is never present); epochs 1–2 and positive versions (1–4) as order classes, since version 0 is malformed on the wire; fact age as Fresh/Stale/Future classes (exact second boundaries are native-tested); Identity reachability as Answer/Unreachable/Malformed; one session slot whose generation increases on each login. | No HTTP status, cookie/Bearer, CSRF, 409 session fence, admission lease, 15 s bound, token hashing, rotation, SQL locking or RPC deadline claim. |
| Mismatch 1 (reported, not modeled) | The contract lists an "other subject" read as a revoking difference. The implementation's `SecurityState::from_response` refuses a reply naming another subject as `MalformedState` → `503` with **no** revocation, so `RevokeReason::SubjectMismatch` is unreachable through the shell. | The model has no well-formed other-subject reply. Owner decision needed: revoke (contract) or protocol failure (code). |
| Mismatch 2 (reported, unconstrained) | The contract says "a write that failed is redone at the next admission". The implementation redoes it only if the next read still differs: if Identity matches again first (e.g. a restored file is put back), it admits the unrevoked session. | The model's state space contains that implementation path only for completeness; no property or run asserts it. `run.failed-revoke-write` asserts the redo only while the difference persists. Owner decision needed: a durable pending-revoke marker, or a narrower contract sentence. |
| Needs decision (unconstrained) | Removing a subject from the Studio roster denies admission without revoking; whether re-adding it may re-admit the same session is not stated. | `run.studio-roster` asserts only the denial. |
