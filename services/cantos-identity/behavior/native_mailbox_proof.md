# Draft: `cantos.identity.native-mailbox-proof` (#334/#335, v1 signup)

Module-owned inventory of [`cantos.identity.native-mailbox-proof`](../../../specs/behavior/catalog.json). The [root inventory](../../../specs/behavior/inventory.md) keeps the shared authority framing; the registry owns the stable ID and lifecycle.

One native Identity Theatre-signup mailbox proof, from issued challenge to the single commit that
consumes it and creates the account. Model: [native_mailbox_proof.qnt](native_mailbox_proof.qnt).

| Classification | Authority / fact | Model consequence |
| --- | --- | --- |
| Approved requirement | [ADR 0045](../../../docs/decisions/0045-v1-email-password-sign-in.md#decision) (v1 email/password with a mailed proof; login grants no Studio/Admin authority); [Identity RPC](../contracts/identity/v1/README.md#one-command-setup-decision) one-command `CompleteTheatreSignup`: the proof presenter chooses the password, consumption and account/credential creation are one storage transaction, receipts/polls/`REPLAYED` are history, not authority; [Identity auth v1](../../cantos-server/contracts/auth/identity-auth/v1/README.md#email-link-and-signup): the fragment link means opening/prefetch consumes nothing, completion issues no session. | Properties `explicit-only` and `single-account-effect`. `no-authority` and the inspection half of `explicit-only` are **scope declarations**: no modeled step writes authority or changes state on inspect, so their controls check assertion sensitivity, not the absence of an implementation path. Lifecycle stays `draft`. |
| Approved storage contract | [Mailbox store v1](../docs/mailbox-store-v1.md#secrets-and-atomic-transitions): binding = operation + instance epoch + intent; the epoch is checked even before receipt replay; exact expiry second excluded; clock before issuance refuses; Consumed/Cancelled terminal; replacement needs a lifetime-unique locator/secret and retires the old one; a plan is applied only by comparing the complete expected snapshot; `Rejected` and `Unknown` commit faults stay distinct and an unknown outcome is reconciled with the identical command. | Properties `consumed-within-bound-window`, `terminal-sticky`, `retired-locator-rejected`, `plan-has-no-effect`, `commit-compares-snapshot`, `only-committed-effects` (a rejected, no-op or `UnknownLost` step leaves durable state unchanged); runs `stale-plan`, `lost-response`, `lost-before-commit`. |
| Implemented independently of this model | Pure [`MailboxProof`](../src/domain/mailbox_proof.rs) `plan_confirmation`/`plan_cancellation`/`plan_replacement` returning a `#[must_use]` `ProofTransition`; the [proof store](../src/persistence/proofs.rs) (epoch → receipt replay → explicit action → binding → locator → secret digest → plan → apply → receipt) and [`complete_signup`](../src/persistence/signup.rs) composing confirmation with subject/email/credential/completion rows in one write transaction. | The model's confirmation precedence follows that store order. Replacement follows the core then the store: pending checks, current locator reused, before issue, cooldown, then lifetime uniqueness of any earlier locator (a store constraint, `LocatorNotUnique`). The public RPC projects every denial to a generic `PERMISSION_DENIED`; precedence is not a wire contract. A test-only [pure-core observer](../src/quint_conformance_tests.rs) is registered (#106): `--conformance` calls the real `plan_*` planners and checked constructors, while the epoch/receipt/secret-class/unknown-operation checks, lifetime-unique locator set, held plan, compare-and-replace, commit fate and account counter are a **disclosed synthetic shell**, labelled per checkpoint. It is not store, SQL, RPC or E2E acceptance ([protocol](../../../specs/behavior/observation-protocol.md#native-identity-auth-observation-protocol-v1)). |
| Finite assumption | One workflow (operation 1, epoch 1, Theatre signup); locators 1–3 as equality classes; a secret is the class of the locator it was minted for (0 = forged); time classes 0–5 with issue 1, TTL 2, cooldown 1, and backwards clock observations; `explicit` is the adapter-established action. Plan and commit are separate steps so an interleaved cancel/replace can make a plan stale; because the implementation computes the plan inside the committing transaction, `settle` re-evaluates the window at the commit instant. | No entropy, digest, constant-time, SQL isolation, concurrent writer, restart, mail, rate budget or transport claim. `UnknownApplied`/`UnknownLost` abstract a lost commit acknowledgement. |
| Gap / not modeled | (1) `CredentialRecovery` intents exist in the core and store, but recovery is deferred by ADR 0045 §3: recovery classes appear only as wrong-binding inputs. (2) Cancellation has no caller authorization or transport yet (store: "its future shell"); `cancel` is an owner-internal step. (3) Detecting a restored Identity file needs future epoch rotation ([security store](../docs/security-store-v1.md#startup-and-mutations)); the model covers only a presented epoch that differs from the store's. (4) `StartTheatreSignup` budgets, existing-address handling and `EmailTaken` remain native tests. | None of these is decided or promoted by simulation. |
