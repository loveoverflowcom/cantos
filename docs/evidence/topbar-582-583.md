scope. Each app was checked at 320/390/1280 CSS px × Light/Dark/System × vi-VN/en: **36 measured

## Deferred acceptance and residual risk

- Android runtime: the configured API-35 AVD refused startup because it needed 7372.8 MB for its
  userdata partition with 5905.7 MB available. The read-only attempt changed no device data. After
  sufficient space is available, launch the emulator, use the existing debug APK with `adb install -r`
  and `adb reverse tcp:8080 tcp:8080`, then check theme/locale/account, native safe areas, large text
  and touch/TalkBack. Assignment remains with the issue owner.
- iOS compile/runtime: NOT_RUN. Installed Kotlin/Native versions are 2.2.0/2.4.20, not the required
  2.2.20, and no available simulator was listed. Prepare the pinned toolchain, run
  `cargo xtask theatre-host ios-build --kotlin-native-home PATH`, then perform simulator/device and
  VoiceOver checks. Android compilation is not iOS evidence.
- Authenticated Web account/avatar flows and browser storage-refusal injection: NOT_RUN; real
  authenticated fixture/account and controlled browser-storage failure are still needed. Existing
  component and preference tests remain independent evidence, not authenticated-browser acceptance.
- A fresh Web 200% text pass, host OS appearance changes, screen readers, touch hardware,
  reduced-motion runtime and deployed acceptance remain NOT_RUN. Browser zoom shortcuts did not
  change the test browser's scale; no 200% browser result is inferred from that attempt or the JVM.
- No media, release, schema, rights, publication, provider, session or deployment behavior changes.
  No shared qualification hashes or required gates were relaxed. Incomplete acceptance remains
  explicit in the issues/PR rather than being counted as a completed criterion.
